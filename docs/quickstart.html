dddown is a local-first Markdown editor: a single Rust binary, zero external network dependencies, live inline rendering. Your notes are plain Markdown files in a workspace — no proprietary format, no lock-in.

01它擅长什么What it does well

✒️

行内渲染Inline rendering

光标离开该行即就地渲染：KaTeX 公式、图片缩略、链接只显示文字、粗体/斜体真字形；光标落回即恢复源码。Typora 式交互。When the caret leaves a line it renders in place: KaTeX math, image thumbnails, text-only links, real bold/italic. The source returns when the caret lands back — Typora-style.

🪶

沉浸式写作Immersive writing

打字机滚动让光标始终居中；专注模式高亮当前段落、淡化其余；光标呼吸、源码语法标记淡化至 25%。Typewriter scrolling keeps the caret centered; focus mode highlights the current paragraph and fades the rest; breathing caret; syntax marks faded to 25%.

📖

WASM 解析 + 增量 DOM 更新，150ms 防抖；支持 Mermaid 图、代码高亮、数学公式、[[wikilink]] 跳转；预览跟随光标定位。WASM parsing + incremental DOM updates, 150ms debounce; Mermaid, code highlighting, math, [[wikilink]] jumps; the preview follows your caret.

🀄

宋体衬线、kerning、悬挂标点、图注与嵌套列表间距逐项校准，书卷气亮色 + 低饱和深蓝灰暗色双主题。Serif CJK with kerning, hanging punctuation, captions and nested-list spacing tuned pixel by pixel. Book-like light theme + desaturated dark blue-grey.

💾

02安装与运行Install & Run

方式一：发布二进制（推荐给使用者）Option A: release binary (recommended for users)

构建一次，之后分发单个文件，运行机器上不需要 Node：

# 在构建机器上执行一次
cd web && npm run build && cd ..
cargo build --release

# 产物拷到任何机器直接运行
./dddown                          # 默认工作区 ~/Documents/Notes
./dddown --workspace ~/my-notes   # 指定工作区

Build once, then ship a single file — the target machine doesn't need Node:

# Run once on the build machine
cd web && npm run build && cd ..
cargo build --release

# Copy the artifact anywhere and run it
./dddown                          # default workspace ~/Documents/Notes
./dddown --workspace ~/my-notes   # pick a workspace

方式二：从源码运行（三步）Option B: run from source (three steps)

依赖Dependency版本Version用途Purpose

cd web && npm install    # 1. install deps
npm run build            # 2. build web/dist

启动行为：监听 127.0.0.1 随机端口（不抢 8080）；自动打开默认浏览器；每次启动生成随机 token，访问必须携带；工作区目录不存在时自动创建。

Startup behavior: listens on a random 127.0.0.1 port (never fights over 8080); opens your default browser; generates a random token per launch that every request must carry; creates the workspace directory if missing.

进去之后按顺序试一遍，五分钟内摸清全部核心能力：

1. 新建文件 — 侧栏顶部输入框输入文件名（如 test.md）回车。

2. 自动保存 — 打字后状态栏右下角出现「未保存」，约半秒变「已保存」；到工作区目录确认文件已落盘。

3. 行内渲染 — 写一行 这是 **粗体** 和 $x^2$，光标移到下一行：粗体变真字重、公式就地渲染；光标移回来，源码复原。

4. 片段补全 — 新起一行输入 tbl，补全弹层出现后按 Tab，表格模板展开，继续按 Tab 在字段间跳转。

5. 全文搜索 — ⌘P（Windows/Linux：Ctrl+P）弹出，关键词同时匹配文件名与内容。

Once you're in, walk through these steps to cover every core capability in five minutes:

1. Create a file — type a name (e.g. test.md) into the input at the top of the sidebar and press Enter.

2. Autosave — after typing, the status bar shows "unsaved", then "saved" within half a second; check the workspace directory to confirm the file landed on disk.

3. Inline rendering — write a line like This is **bold** and $x^2$, then move the caret to the next line: the bold becomes real weight, the math renders in place; move the caret back and the source returns.

4. Snippets — on a new line type tbl, press Tab when the completion popup appears, and a table template expands; keep pressing Tab to jump between fields.

5. Full-text search — ⌘P (Windows/Linux: Ctrl+P) opens it; keywords match both file names and content.

04写作体验进阶Writing experience, deeper

专注模式

⌘⇧D 开启：只有当前段落保持正常对比度，其余段落淡化。鼠标悬停可临时恢复查看上下文。长文写作时配合打字机滚动（光标始终停留在视口中央），注意力不散。

预览跟随光标

光标进入新的章节（heading），预览区自动平滑滚动到对应位置——长文档里不用手动对齐两栏。

主题与字体

⌘⇧T 循环切换四种主题（书卷亮 → 书卷暗 → 现代亮 → 现代暗）；⌘⇧F 切换宋体/无衬线，与主题解耦自由组合。等宽字体本地打包，离线也正常渲染。所有选择随刷新记忆。

外部修改同步

用 vim 改了文件、git pull 拉了新内容、iCloud 同步进来——编辑器自动加载最新内容，不会互相覆盖。

Focus mode

⌘⇧D turns it on: only the current paragraph keeps full contrast while the rest fades. Hover temporarily restores context. Combined with typewriter scrolling (the caret stays at the viewport center), your attention never drifts.

Preview follows the caret

When your caret enters a new heading, the preview smooth-scrolls to the matching section — no manual two-pane alignment in long documents.

Themes & fonts

⌘⇧T switches between Book (light serif) and Night (desaturated dark blue-grey); ⌘⇧F toggles serif/sans-serif. Monospace fonts are bundled locally, so rendering works offline. All choices persist across reloads.

External change sync

Edit a file with vim, pull with git, or let iCloud sync it in — the editor loads the latest content automatically, and nothing overwrites anything else.

06配置与数据Configuration & data

配置文件：~/.dddown/config.toml。所有字段可省略，缺省用默认值；文件不存在或内容非法时整体回退默认，服务照常启动。

Configuration lives at ~/.dddown/config.toml. Every field is optional and defaults apply; a missing or invalid file falls back to defaults entirely, and the server still starts.

[server]
port = 0                          # 0 = random port (default)
workspace = "~/Documents/Notes"   # ~ expansion supported
token = "your-secret-token"       # omit = random token per launch

[editor]
font_size = 15
tab_size = 2

[shortcuts]
save = "mod-s"
search = "mod-p"                  # all 7 actions optional

07常见问题FAQ

启动报错 failed to bind port？Startup fails with "failed to bind port"?

端口被占用。默认随机端口不会遇到；如果你在 config.toml 里配了固定端口，换一个或删掉该行。

The port is taken. The default random port never hits this; if you pinned a fixed port in config.toml, pick another one or remove the line.

浏览器没有自动打开？The browser didn't open automatically?

从终端输出里复制 http://127.0.0.1:端口/?token=… 完整 URL 手动打开即可。

Copy the full http://127.0.0.1:PORT/?token=… URL from the terminal output and open it manually.

页面提示 404 或无法访问？The page shows 404 or can't be reached?

URL 必须带完整 token，且 token 每次启动都会变化。从当前终端输出重新复制 URL。

The URL must carry the full token, and the token changes on every launch. Re-copy the URL from the current terminal output.

cargo run 首次启动很慢？First cargo run is slow?

首次编译要拉取并构建全部依赖，几分钟正常；之后增量编译只要几秒。

The first compile fetches and builds every dependency — a few minutes is normal. Incremental rebuilds take seconds afterwards.

改了 web/src 代码没生效？Changes under web/src have no effect?

debug 模式读的是 web/dist 构建产物，不是源码。重新 npm run build，或用开发模式（MD_PORT=41937 cargo run + npm run dev 享受 HMR）。

Debug mode serves the built web/dist artifacts, not the source. Run npm run build again, or use dev mode (MD_PORT=41937 cargo run + npm run dev for HMR).

保存会覆盖我在别处做的修改吗？Will saving overwrite changes I made elsewhere?

不会。编辑器只在你输入过内容之后才自动保存；外部修改进来后不会触发保存路径（防回声循环），git pull、iCloud 同步进来的内容不会被空写覆盖。

No. The editor only autosaves after you've actually typed; incoming external changes never trigger the save path (echo-loop protection), so git pulls and iCloud syncs are never clobbered.
